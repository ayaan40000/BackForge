All notable changes to BackForge. Versions follow the roadmap in `docs/ROADMAP.md`.

## v2.5 — The Coach Gets a Memory (2026-11-03)

- **Readiness score (Today → Coach's read).** Sleep + today's pain + pain trend between check-ins + recent session load → a 0–100 morning readiness call (full / trimmed / micro / relief), shown with the full arithmetic — every point is explained, per the roadmap exit rule. Live Mode's default energy now derives from readiness: relief → flare protocol, micro → low, trimmed → okay. Pain ≥ 7 forces relief regardless of score.
- **Per-exercise response learning.** Each exercise is judged on next-morning pain after days it was logged (needs a check-in that day and the next): ≥2 readings and an average fall of 0.75+ → **Helps**; an average rise of 1.0+ → **Watch**; otherwise Neutral/Learning. The Live builder sorts Helps first and Watch last and prints the verdict sentence in "Why this workout?". All verdicts with their evidence live on Progress → "What the coach has learned".
- **Smart streak repair.** Missing exactly one day leaves the chain repairable: the Today card offers a repair session (smallest Live build). Logging it bridges the missed day at reduced credit — the missed day itself never counts, and two consecutive misses still break the chain. Repair sessions log as their own kind (`repair`).
- **Deload intelligence.** Weekly average pain compared across three week-windows: two consecutive rising weeks → deload proposed on Today; two falling weeks → retest invitation; a single rising week shows a plain watch note. An active deload week (7 days) trims the strength session to 3 exercises, drops one Live main exercise, caps sets at 2, and says so in every "Why" receipt.
- **Weekly review card (Progress).** Sessions this week vs last, average pain and its delta, gate status, one auto-picked win, one auto-picked adjustment, and a one-tap .txt export.
- **Protein floor tracker (Progress).** Bodyweight (lb) → floor of 1.6 g/kg/day; quick-add chips (+10/+25/+40 g) and custom grams; today's bar plus floor-hit days this week; low-protein weeks surface as the weekly review's adjustment. Photo-first logging is **not** in this version — it stays on the roadmap, and the in-app card says so.
- State: `backforge_v1` gains `protein`, `bodyweightKg`, `deloadUntil` — old saves merge over the defaults, nothing is lost. App footer version label bumped to v2.5 in the page itself.
- Verified: JS syntax on all 4 script blocks; 25-case functional harness over the extracted production functions (readiness bands incl. flare override and stale check-in, helps/watch/learning verdicts, repair offer + bridge + two-miss break, deload propose/retest/active/expired, protein target math, weekly review composition, builder integration incl. deload dose caps and flare relief-only, no extension-trap exercises served); v2.0.1 skip-fix regression re-run clean; backend suite unchanged at 78 passing (the engine port of the v2.5 logic is a follow-on, not in this release).

## v2.0.1 — Assessment skip fix (2026-11-02)

- **Fixed the phantom "Glutes are firing" finding in the app.** `scoreAssessment()` stored a skipped answer as the string `'skip'`, which is truthy in JS — so skipping every glute test (firing order, single-leg bridge, clamshell) satisfied the "glutes are firing" branch and reported a Clear finding from no data. The scorer now cleans `'skip'` to `null` for every answer before any check runs, exactly as the backend engine does. Stored answers are not changed; only scoring sees the cleaned copy.
- This restores the documented invariant in the live app: skipped tests are no data and can never generate a finding — including the partial case (one side skipped, the other clean no longer reports "firing"; both sides genuinely clean still does).
- Verified: JS syntax on all script blocks; functional scoring cases — all tests skipped → zero findings, glute tests only skipped → zero findings, clean glutes both sides → "Glutes are firing", two-hit right-side inhibition still detected, the full expected profile still scores its 10 findings; backend suite unchanged at 78 passing.

## Backend engine + exercise directory (2026-11-01)

- **BackForge Engine v0.1 (`backend/`).** FastAPI + SQLite port of the frontend's assessment scoring (all 13 tests, same finding wording and severities), plan generator, Live workout builder, and rolling 14-day progression gate. Endpoints: `/health`, `/exercises` (filtered, profile-aware), `/profile`, `/assess`, `/plan`, `/workout/live`, `/log/checkin`, `/log/session`, `/progress`, `/progress/promote` (gate-enforced — 409 until the gate is ready), `/state/export`, `/state/import` (round-trips the app's `backforge_v1` shape).
- **Safety invariants as tests — 78 passing.** Trap exercises (Jefferson curl, Russian twist, banded crunch) are never served; both-knees-to-chest never appears for any profile; extension-intolerant profiles exclude press-ups, sphinx, and prone extension (contra tags plus a spinal-load fallback rule); pain ≥ 7 yields relief-only plans and Live builds; gate boundaries tested (average pain exactly 3.0 passes; day-20 activity falls out of the window); skipped answers produce zero findings.
- **One frontend bug deliberately not ported:** in the app, a skipped glute test could read as "firing" (the string `skip` is truthy in JS). The engine cleans skips to no-data before scoring, per the skip = no data invariant. (The app itself was fixed to match in v2.0.1, 2026-11-02.)
- **Exercise directory: 26 → 48 exercises** (`backend/data/exercises.json`; human-readable `docs/EXERCISE-DIRECTORY.md`). New coverage: hip internal rotation (seated and standing banded IR, 90/90 lift-off), QL (suitcase carry, seated QL stretch), prone hip-extension firing drill, sciatic nerve glide, deep neck flexor holds, 360° breathing and brace. Validated: 0 loaded-flexion and 0 loaded-rotation entries; the only 3 extension-biased entries all carry the extension-intolerant exclusion tag.

## v2.0 — Live Mode (2026-11-01)

- **Live workout partner (new Live tab).** Three taps — time on hand (5/10/20/35/50 min), body feel (great / okay / low energy / pain flare), and caveats (standing hurts, right/left side touchy, knees sore, no bands, quiet) — build a complete session: warm-up, main work, cool-down. One start button; no other decisions.
- **Self-updating defaults.** The default workout re-derives after every logged session and assessment from: assessment findings + severity, per-exercise logged history (new `S.exLog` — the guided player now records it too), today's pain/sleep check-in, and the A/B/C + Zone 2 weekly slot. A "Why this workout?" receipt explains every build in plain language.
- **Partner player.** Set × side steps with a coach cue on every step, hold timers, 45s auto-rests, progress bar, one-tap **Regress** (modify, don't stop), guilt-free **Skip** (skip = no data), resume after interruption (persisted in `S.livePlayer`), and a celebration finish: specific praise, a real-person quote, streak impact, and a one-tap pain score that feeds the progression gates.
- **Flare safety.** Flare energy (or a pain ≥ 7 check-in) runs the relief protocol only — Live Mode cannot build a strength session on a flare day.
- **Motivation system.** Daily rotating quotes from real, attributed people (James Clear, Mark Twain, Bruce Lee, Marcus Aurelius, Vince Lombardi, Muhammad Ali, Jim Rohn, Seneca, Confucius, Lao Tzu, Nietzsche, Henry Ford, Arnold Schwarzenegger, Jocko Willink, Karen Lamb, Jim Ryun, Will Durant on Aristotle); rotating coach notes on proven anti-procrastination mechanics (2-minute rule, don't-break-the-chain, implementation intentions, temptation bundling, future-self continuity, self-compassion research, identity voting).
- **Habit tracking.** Week dots (Mon–Sun chain view), milestone badges (first session, first Live workout, 3-day chain, week unbroken, 10/25/50 sessions, 14-day streak, gate opened) with a "next badge" target, and a done-today state that reframes extra work as bonus.
- Today view: a "already in the bank" encouragement line once today is logged.
- In-app roadmap cards rewritten to the version roadmap (v2.0 → v5.0). Full roadmap: `docs/ROADMAP.md`.
- Tested: JS syntax on all script blocks; jsdom functional suite in seeded (assessment + history) and fresh states — builder sections/budgets/caveats/flare, strength-day and rest-day paths, full player flow to logged session, regress path. All green.
