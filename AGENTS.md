# AGENTS.md — how to maintain BackForge (for Muse, Claude, and any other builder)

Read this first. It is short on purpose. The design authority is `docs/DESIGN-PROTOCOL.md`; the product direction is `docs/ROADMAP.md`; the safety rules are in `CLAUDE-REVIEW.md` §5 and repeated below.

## 1. What runs where

| Path | What it is | Who edits it |
|---|---|---|
| `index.html` | The app shell (v4.5+). Loads `app/css/*` and `app/js/main.js`. No build step. | builders |
| `app/js/engine/` | Pure logic: safety layer (`library.js`), plan, Live builder, readiness/streak/gate, dose reader. **No DOM.** | builders, with tests |
| `app/js/live/` | Real-time Live mode: `compiler.js` (timeline), `coach.js` (dialogue scheduler), `player.js` (clock), `audio.js`, `voice.js`, `session.js` (wires it all) | builders, with tests |
| `app/js/screens/`, `app/js/ui/` | Preact + htm components (no JSX, no bundler) | builders |
| `app/css/tokens.css` | **The only place** colours, glass, type, spacing and motion values are defined | builders |
| `app/vendor/` | Pinned third-party files (see `app/vendor/VERSIONS.md`). Never edit; replace whole files. | builders |
| `backend/data/exercises.json` | Canonical exercise library (shared with the Python backend) | **Muse: data** |
| `data/exercises-desk.json` | The 8 desk & travel moves (same schema) | **Muse: data** |
| `data/coaching.json` | Per-exercise extras: `setupCue`, `focusCue`, `helps`, `gotIt`, `videos`, `contexts` | **Muse: data** |
| `data/voice-lines.json` | Everything the Live coach can say | **Muse: data** |
| `data/assessments/movement-tests.json` | The 13 movement tests (text + options; scoring is `app/js/engine/assessment.js`) | builders (text edits OK) |
| `data/assessments/posture-tests.json` | The posture check: 8 band + 5 bodyweight tests, areas, per-grade plan changes (grading is `app/js/engine/posture.js`) | builders (text edits OK) |
| `data/demo/demo-state.json` | Demo history (generated by `tools/make_demo_data.mjs`) | regenerate, don't hand-edit |
| `classic/index.html` | The v4.0 single-file app. Still hosts the check-ups (assessment, band posture check, photo check + vault, PIN setup). Same data. | only to fix bugs; features go to the new app |
| `backend/` | Optional FastAPI port of the engine (81 tests) | builders |
| `tools/health_sync.py` | Muse's Health Connect → sync-file generator | Muse |

Both apps share one localStorage object, `backforge_v1`. The new app reads it whole and writes it whole, so fields it doesn't know about survive. Demo mode uses `backforge_demo` and never touches real data.

## 2. Before you push — always

```bash
npm test                 # node --test tests/*.test.mjs   (engine, live, data — no installs needed)
npm run test:classic     # classic app harnesses (needs jsdom in /tmp/bf-harness, see dev/harness-v4.mjs)
node dev/parity-assessment.mjs   # assessment/posture scoring must equal the classic app (same jsdom)
cd backend && python3 -m pytest -q
# optional, real browser:  npm run serve &  npm run test:browser
```

Then: add a plain-English entry at the top of `CHANGELOG.md`, and update `README.md` if behaviour changed. Same push. Bump `VERSION` in `app/js/screens/you.js` and in `sw.js` when you ship.

## 3. Safety invariants — never break (tests enforce them)

1. No loaded spinal flexion, no loaded twisting. Never both knees to chest.
2. Extension-intolerant ⇒ no press-ups, sphinx, prone extension, or lumbar-arch finishes.
3. Pain ≥ 7 today ⇒ relief protocol only. No side-bend (`qlreach`) in the flare protocol.
4. Skipped assessment answers are no data — never a finding.
5. Every exercise keeps a regression (modify, don't stop).
6. The app screens and trains; it never diagnoses. Coach lines never say fix / cure / heal / treat / diagnose, never "no pain no gain".
7. Pain gates progression; the calendar never does.

## 4. Recipes

### Add an exercise
1. Add one object to `backend/data/exercises.json` (or `data/exercises-desk.json` for desk/travel moves):
   `id` (kebab or existing style, **never rename an id** — it keys the user's history), `name`, `category` (core/glute/hip/strength/mobility/warmup/cooldown/relief), `targets`, `equipment`, `dose` (e.g. `"3 × 8 / side · 8-sec holds"`, `"2 × 30 sec / side"`), `cues` (≥ 1), `mistakes`, `regression`, `progression`, `spinal_load` (none/flexion/extension/rotation), `contra` (e.g. `["extension-intolerant"]`).
2. Add a `data/coaching.json` entry with a spoken `setupCue` (≤ 8 words) and `focusCue` (≤ 6 words), no symbols. Videos: `{"channel", "type": "direct"|"search", "url"}` — `direct` only for an ID you verified on the real page; never invent a video ID.
3. `npm test`. The dose reader must understand the dose string (the test fails if not).

### Add or change coach lines
Edit `data/voice-lines.json`. Keep the category. Rules (also in `docs/DESIGN-PROTOCOL.md` §8): second person, ≤ 12 words a sentence, no hype words (crush, smash, beast, burn, kill it), no medical claims, specific praise only for things the app actually knows (set count, side, hold length) — it cannot see the body, so never "your pelvis stayed level". Placeholders: `{name} {ex} {side} {otherSide} {set} {sets} {reps} {sec} {setupCue} {focusCue} {cue} {next} {nextSetup} {minutes} {minsLeft} {moves} {pain} {sleepPhrase} {loadPhrase} {regression} {weakSide} {longest} {rest}`. A line whose placeholders can't be filled is skipped automatically.

### Import health data (Health Connect via Muse)
Muse runs `tools/health_sync.py` and gives the owner one JSON file; the owner imports it under **Progress → Health → Import sync file**. Accepted per-day fields (all optional, range-checked, never zero-filled): `steps, distanceKm, activeKcal, caloriesIn, caloriesOut, zone2Min, sleepMin, sleepDeepMin, sleepRemMin, sleepLightMin, sleepAwakeMin, sleepScore, restingHr, hrvMs, spo2, weightKg, bodyFatPct, vo2max, workouts[{type, min, avgHr}]`. Shape: `{ "kind": "backforge-health-sync", "version": 3, "source": "...", "days": [{ "date": "YYYY-MM-DD", ... }] }`. Validator: `parseHealthPayload()` in `app/js/store.js`; test in `tests/data.test.mjs`.

### Review a photo check (Muse)
Ayaan sends you `backforge-posture-request.json`, plus `side-right.jpg`, `side-left.jpg`, `front.jpg`, `back.jpg` and sometimes `prev-*.jpg` from the last set. Follow the request's `prompt` exactly. It is screening only: no diagnosis, no invented measurements, and `not-assessable` when a landmark isn't visible. Reply with JSON only:
```json
{ "kind": "backforge-posture-result", "version": 2, "requestId": "<from the request>",
  "patterns": {
    "forwardHead": { "grade": "clear|mild|moderate|marked|not-assessable", "confidence": 0.7, "viewsUsed": ["side-right"],
                     "observations": ["Ear ahead of the shoulder line (side-right)"],
                     "consistency": "agrees|photo-shows-more|photo-shows-less|not-assessable", "consistencyWhy": "one sentence",
                     "progress": "better|same|worse|not-assessable" } ,
    "pelvicTilt": {}, "thoracicKyphosis": {}, "shoulderRound": {}, "shoulderAsymmetry": {}, "pelvicObliquity": {}, "lateralShift": {} },
  "summary": "two sentences", "suggestedFocus": ["..."], "notes": "" }
```
`consistency` compares your photo grade with `request.assessment.patterns` (the user's own test grades). `progress` compares with the `prev-*` photos. The app validates every field (`parseResult()` in `app/js/engine/photo.js`) and computes its own consistency too. Photo grades never change the plan; only tests do.

### Add or change a posture test
Add its text to `data/assessments/posture-tests.json` (`id`, `name`, `pattern` apt|head|back|shoulders, `kind` band|bodyweight, `equipment`, `setup`, `inputs[{key,label,options}]`, `planChange` for all four grades, `evidence`). Add a grader with the same id to `GRADERS` in `app/js/engine/posture.js`. `npm test` checks that every input combination grades. Never rename an id or an option value: they are stored in the user's history.

### Change the look
Only through tokens in `app/css/tokens.css`. No raw colours, no inline `style` colours outside tokens, no emoji as icons (use `app/js/ui/icons.js`). Glass is for controls and cards, never on list rows or long text. Check dark, light, "Solid surfaces" and reduced motion.

### Regenerate the demo
`node tools/make_demo_data.mjs` (deterministic). It must never contain a banned move.

## 5. Commit conventions
- Branch `muse/<topic>` or `claude/<topic>`, PR to `main` for the owner's merge, unless told to push.
- Data-only commits start with `data:` and touch only `data/`, `backend/data/`, `tools/sample-payload/`.
- Never force-push `main`. Never commit secrets or the owner's PIN.
- End every work session with: what changed, what's unverified, what's blocked.
